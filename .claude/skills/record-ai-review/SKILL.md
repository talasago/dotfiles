# record-ai-review

ユーザーが AI の出力（コード・設計）をどう評価したかを蓄積するためのスキル。目的は、続けることで「自分がどの種類の誤りを見抜けていないか」を知ること。

AI は自分で評価しない。チャットに無い指摘・理由を AI が考えたり補ったりすると、ユーザーの評価力の記録にならないため。

## ログファイル

`~/claude-records/ai-review-log.md`（実行環境のローカル。git 管理下のリポジトリには置かない）。無ければ作成する。

## 記録モード（引数なし）

このセッションのチャットを振り返り、AI が出力したコード・設計に対する問題を洗い出し、ユーザーが選んだものを記録する。

1. 次の2区分に当たるものを洗い出す
   - `指摘`：ユーザーが AI の出力の問題を指摘した発言
   - `見逃し`：ユーザーがいったん受け入れた出力（指摘せずに次へ進んだ・コミットした等）の問題が、あとからユーザー以外のきっかけで見つかったもの。きっかけの例：テスト・CI の失敗、実行時エラー、レビュアーやレビューボットのコメント
2. 1件ごとに以下を書く
   - **指摘**・**理由**：`指摘` はユーザーの発言をそのまま引用する。ユーザーが理由を言っていなければ「理由：なし」と書き、AI が補わない
   - `見逃し` は、きっかけ（CI のエラー・レビューコメント等）の内容を要約して書く
3. 誤りの種類を1つ付ける。下の分類から選び、当てはまらなければ新しい種類を作る
   - 責務・境界／仕様の読み違い／非機能（性能・運用・セキュリティ）／エラー処理／過剰な実装／命名・可読性／テスト
4. 候補を番号付きの一覧でチャットに出し、残さないものをユーザーに選んでもらう。この時点ではログに書かない。1件も無ければその旨だけ伝える
5. ユーザーが選んだ後、残すものをログに追記し、追記した内容をチャットにも出す

```markdown
## YYYY-MM-DD リポジトリ名
- [指摘|見逃し] 種類：〇〇
  - 対象：path/to/file
  - 指摘：…
  - 理由：…
  - きっかけ：…（見逃しのときだけ）
```

## 振り返りモード（引数が「振り返り」）

ログを読み、種類ごとに `指摘` と `見逃し` の件数を表にする。`見逃し` が多い種類、`指摘` が1件もない種類を挙げる。改善策の提案はしない。
