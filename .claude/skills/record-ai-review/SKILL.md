# record-ai-review

ユーザーが AI の出力（コード・設計）を自分で評価し、その指摘を蓄積するためのスキル。目的は、続けることで「自分がどの種類の誤りを見抜けていないか」を知ること。

AI は評価しない。指摘の中身・理由を AI が考えたり補ったりすると、ユーザーの評価力の記録にならないため。

## ログファイル

`~/claude-records/ai-review-log.md`（実行環境のローカル。git 管理下のリポジトリには置かない）。無ければ作成する。

## 記録モード（引数なし）

1. 対象を確認する：このセッションで AI が出力したコード・設計のうち、どれへの指摘か（ファイルパス等）
2. ユーザーに指摘を書いてもらう。1件ごとに以下が揃うまで質問する。AI から指摘の候補や理由を出さない
   - **指摘**：何が問題か
   - **理由**：なぜ問題か
   - **区分**：`指摘`（その場で見抜いた）／`見逃し`（あとで別のきっかけで気づいた。きっかけも聞く）
3. 誤りの種類を1つ付ける。下の分類からユーザーに選んでもらう。当てはまらなければユーザーの言葉で新しい種類を作る
   - 責務・境界／仕様の読み違い／非機能（性能・運用・セキュリティ）／エラー処理／過剰な実装／命名・可読性／テスト
4. ログに追記する（ユーザーの言葉をそのまま使う。言い換えない）

```markdown
## YYYY-MM-DD リポジトリ名
- [指摘|見逃し] 種類：〇〇
  - 対象：path/to/file
  - 指摘：…
  - 理由：…
  - きっかけ：…（見逃しのときだけ）
```

## 振り返りモード（引数が「振り返り」）

ログを読み、種類ごとに `指摘` と `見逃し` の件数を表にする。`見逃し` が多い種類、`指摘` が1件もない種類を挙げる。改善策の提案はしない。
